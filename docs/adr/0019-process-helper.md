# ADR-0019: Обычный синхронный хелпер запуска процессов

Статус: согласовано пользователем, реализовано; verification ниже.

## Причина и граница

Четвёртый пользовательский OCaml-диалог подтвердил пользу `texts`: с первой
попытки программа дошла с кавычками и переводами строк без маркеров `@Q@`/`@B@`
и без обвинений транспорта; финальные проверки имели exit 0 и последующее
перечитывание исходника. Оставшиеся ошибки Elisp в основном относились к
многоэтажному повторяемому шаблону запуска процессов: незакрытые скобки,
потеря exit status, неявный вывод в текущий буфер и поиск собранного
executable по относительному имени, не работавший в этом окружении без
абсолютного пути. Диалоги различаются, поэтому это не контролируемый
бенчмарк; приватные логи не включаются в репозиторий и не переисполняются.

## Решение KISS

Добавлен обычный Elisp-хелпер `emacs-agent-run-process PROGRAM ARGS &key
(DIRECTORY default-directory)` для вызовов внутри прежнего единственного
`eval_elisp`. Нет нового model tool, process runner, очереди команд,
backend registry, timeout, автоматического выбора команд или интерпретации
успеха.

- ARGS — proper list или vector строк; строки копируются без properties.
- Никакой shell-обёртки: PROGRAM и ARGS передаются в нативный `process-file`
  буквально, без expansion/quoting/unescape. Использовать shell — явный
  выбор PROGRAM.
- Bare-имена ищутся нативным PATH-lookup. Пути с directory-компонентом
  раскрываются относительно DIRECTORY, затем `file-local-name`: это чинит
  относительный lookup executable, замеченный в диалоге. Квалифицированный
  remote PROGRAM обязан совпадать по хосту с DIRECTORY.
- Вывод — свежий приватный disposable buffer, stdout и stderr объединены;
  буфер всегда удаляется, текущий буфер не выбирается и не меняется.
- Результат: `:output`, `:directory` (раскрывается в абсолютный cwd),
  `:command` (программа и argv фактического вызова), `:exit` (integer или
  signal string). `:exit` — последний ключ, чтобы F3 tail сохранял статус
  после шумного stdout. `:command` называет вызов, а не resolved-бинарник.
- Запуск/quit/ошибки распространяются; статус не изобретается и retry нет.

Хелпер не сохраняет буферы, не редактирует, не выводит «проверено», не
угадывает проверенный файл, не чистит сгенерированные артефакты и не
откатывает эффекты процесса. Сохранение и интерпретация результата —
как в ADR-0017. Длинные команды требуют существующего асинхронного
workflow. Результат не бюджетируется отдельно хелпером; применяется
обычный F3 limiter `eval_elisp`.

## Смежные улучшения

`emacs-agent-replace-region` теперь называет конкретный недопустимый
аргумент (START/END/OLD/NEW/:tick) с коротким значением, а не общий список
требований. В диалоге модель передала программу как OLD и nil как NEW;
предметная ошибка позволяет исправиться без чтения всей документации.
Порядок проверок не изменился; guards/undo/rollback прежние.

Prompt: пример disk-check использует хелпер; добавлена строка про
run-process/executable-find. Prompt 5393 символа (<5400), все прежние
контракты сохранены; это не измерение token usage.

## Проверка

379 ERT, warnings-as-errors compilation, diff-check. Тесты: реальные
POSIX `sh` (не пользовательский Fish), комбинированный stderr/exit,
literal argv (spaces/quotes/Unicode/shell-метасимволы без интерпретации),
cwd и относительный executable, bare-name PATH, изоляция повторов и
удаление output buffers, plain-копии без properties, remote-синтаксис
через mocks без соединений, отклонение cross-host, невалидные входы до
запуска, сохранность источника при ошибках/quit, артефакты F3 (0600/0700,
tail сохраняет `:exit`, повторного запуска нет), интеграция с `texts`
каналом и именование конкретного аргумента в ошибках replace-region.

Нет provider calls, live user-Emacs/hot-load, исполнения приватных
диалогов или установки пакетов. Улучшение поведения модели ещё не измерено
контролируемым бенчмарком.
