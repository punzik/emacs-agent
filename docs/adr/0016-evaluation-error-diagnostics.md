# ADR-0016: Диагностика eval без новых tools и отката

Статус: согласовано пользователем, реализовано; offline verification ниже.

## Причина

В предоставленном пользователем диалоге про OCaml модель долго ошибочно
диагностировала обычные ошибки Elisp как повреждение транспорта. Отдельная
нескопированная операция очистила исходный буфер, тогда как проверка сохранённого
файла завершилась успешно. Нужны сведения о месте/фазе ошибки и реальном состоянии
редактора, а не sandbox, дополнительный tool или обязательный execution ledger.
Приватный диалог не включается в репозиторий и не переисполняется.

## Решение

`eval_elisp` сохраняет один строковый аргумент и строковый результат. Формы
по-прежнему читаются и выполняются последовательно с lexical binding: нет полного
preflight разбора, повторов, автоматического сохранения, восстановления или
отката. Обычный успешный результат без изменения исходного буфера не меняется.

При ERROR/QUIT добавляются:

- фаза `read`/`eval`, номер формы и число успешно завершившихся форм;
- начало верхнеуровневой формы; при ошибке чтения — позиция остановки reader;
- 1-based позиции/строки в символах, 0-based колонки в символах, не display columns;
- короткий escaped excerpt и best-effort syntax-table hint об открытой строке
  или списке; это не обещание точной диагностики любого reader-синтаксиса;
- явное предупреждение об эффектах: текущая форма при read-ошибке не исполнялась,
  предыдущие могли исполниться; неуспешная eval-форма сама могла изменить редактор.

Последняя строка ERROR/QUIT сохраняет прежний формат и остаётся после диагностики,
чтобы F3 tail сохранял короткую исходную ошибку после шумного stdout. Первая строка
диагностики содержит и фазу, и condition для короткого journal preview.

## Короткий стек

Локально привязанный `debugger` собирает максимум восемь имён функций до границы
`eval`. Аргументы, определения функций и closure environments не сохраняются и не
печатаются. Условие сопоставляется по символу и identity хвоста signal data с
фактически пойманной ошибкой: стек пойманного внутреннего исключения нельзя
приписать более поздней ошибке. Ошибка в unwind cleanup замещает раннюю ошибку
обычным образом. При успехе собранный внутренний стек отбрасывается.

Используются локальные debug flags и handler `(debug error)`, не глобальный advice
и не интерактивный `debug`. Внутри capture отключены рекурсивный debugger и quit;
ошибки самого capture перехватываются. Локально привязанный внутренний
`internal-when-entered-debugger` сбрасывается в -1: без этого Emacs подавляет
повторный вход без промежуточного keyboard event. Его внешнее значение и внешние
debugger/debug flags восстанавливаются при выходе. Это осознанная небольшая
зависимость от внутренней переменной Emacs, существующей в 28.1.

Сигнатура берётся у уже загруженного определения через `help-function-arglist`
без preserve-names/documentation lookup и без autoload. Имена аргументов поэтому
могут быть generic. Ошибка получения сигнатуры не скрывает доступные имена кадров.
Стек обозначен как доступные кадры, не как доказанное точное место исходного кода.
Если код подавляет debugger или capture недоступен, явно возвращается unavailable.

Функция печати ограничивает глубину, длину и число выдаваемых символов; не сначала
сериализует целиком большой объект. Однако строгой границы allocation нет:
`backtrace-frame` временно материализует аргументы кадра до их отбрасывания.
Unrestricted Elisp может менять debug machinery; это не изоляция исполнения.

## Состояние исходного буфера

До/после вызова читаются live status, buffer name, visited file, character tick,
modified flag и полный размер в символах, без чтения текста, widening, движения
point или изменения undo. Это фактический буфер выполнения, не обязательно
выбранное окно или произвольная цель выражения.

Только при net change добавляется краткий `Source buffer changed`: identity до
вызова и изменившиеся поля с парами `(before after)`. `:whole-characters` всегда
считает весь буфер, независимо от narrowing. Переименование, уничтожение и смена
modified flag тоже видимы. Это не журнал всех промежуточных изменений; остальные
буферы и внешние эффекты не проверяются. Новых buffer IDs/registries нет.

Сводка следует за успешным `=> VALUE`, чтобы не ломать обычное чтение возвращённой
Lisp-величины. В случае ошибки она находится перед последней ERROR/QUIT строкой.
Всё проходит через прежний F3 limiter: полный текст приватный, повторов eval нет,
очень маленький budget может обрезать диагностику/значение. Ошибки диагностики
изолированы и не заменяют исходную ошибку или уже совершённые эффекты.

## Проверка

333 ERT, clean warnings-as-errors compilation и diff-check. Runtime — Emacs 30.2;
совместимость используемых debugger/frame API с 28.1 проверена по интерфейсам и
исходникам, но отдельный runtime на 28.1 не запускался. Нет provider calls,
hot-load в пользовательский Emacs или replay исходного диалога.

Тесты включают незакрытые конструкции, Unicode/tab координаты, позднюю read-ошибку,
внутренний `read` с фазой eval, частичные эффекты, raw erase, narrowing/point/mark/
undo, rename/kill, modified flag, чужой буфер, циклические/большие значения,
сбой диагностики, повторные ошибки без keyboard input, сигнатуры, user debugger,
обычные и `(debug error)`/`condition-case-unless-debug` handlers, throw/quit,
unwind cleanup, stale/inhibited capture, отсутствие closure dump и F3 artifacts.
