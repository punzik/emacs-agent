# ADR-0002: Буферные правки с undo и штатным сохранением

Статус: принято пользователем; реализовано и проверено offline.
83 ERT и byte compilation с warnings-as-errors проходят. Пользовательский
live smoke подтверждён журналом: шесть замен через helper, перечитывание после
OLD mismatch без обхода защиты, штатный `save-buffer`. Пользователь отдельно
подтвердил работоспособность undo. Итоговый file-modtime явно не измерялся.

## Контекст

В исследованной пользовательской сессии агент менял посещающие буферы через
`erase-buffer`/`insert` и `replace-match`, но сохранял через трёхаргументный
`write-region`, затем `set-buffer-modified-p nil`. Это записывает диск, но не
обновляет сохранённое file-modtime буфера. Воспроизведение подтверждает:
текст обновлён и undo есть, однако `verify-visited-file-modtime` возвращает nil.
Само последующее перечитывание и причина исчезновения undo логом не установлены.
Также вызван несуществующий `write-buffer`: уже сделанные изменения остались
после ошибки. Полный приватный лог в репозиторий не включается.

## Решение

Добавить обычную Elisp-функцию в `emacs-agent-helpers.el`, не новый LLM tool:

```elisp
(emacs-agent-replace-region BUFFER START END OLD NEW :tick TICK :widen t)
```

- BUFFER — явный живой буфер или его точное имя, не имя файла. Для посещения
  файла использовать штатный `find-file-noselect`, без подавления конфликтов.
- START/END — абсолютные символьные позиции, END исключителен. OLD должен
  точно совпасть с текущим текстом диапазона (без text properties).
  Для вставки START=END и OLD="", для удаления NEW="".
- `:tick` обязателен: целочисленный ожидаемый `buffer-chars-modified-tick`.
  Его можно получить через helpers чтения. Не угадывать старые позиции:
  при несовпадении текста/tick — ошибка до редактирования.
- Уважаются narrowing, read-only и стандартные change hooks. Временный widening
  только по `:widen t`. Undo должен уже быть включён: если отключён, ошибка,
  а не молчаливое изменение пользовательской настройки.
- Если посещаемый файл изменён снаружи, ошибка до редактирования: не делать
  автоматический revert и не снимать modified. Проверка modtime не является
  защитой от гонки с внешним процессом после проверки.
- Одна замена — атомарная группа и отдельный undo-шаг с границами до/после.
  Старая история остаётся. Ошибка внутри правки откатывает её текст в целевом
  буфере, но не произвольные побочные эффекты hooks в других буферах/файлах.
- Point/mark и narrowing восстанавливаются как живые координаты Emacs,
  с естественным смещением при изменении текста, не как старые числа.
  Окна не выбираются. Неизменённый текст OLD=NEW — no-op без undo-записи.
- Результат — небольшой plist `:buffer`, `:start`, `:end` нового диапазона,
  `:tick` после правки, `:modified`, `:changed`. Печатный результат должен
  поместиться в evaluator budget; иначе правка отменяется, не скрывается
  за ошибкой сериализации после успешного изменения.

Сохранение — отдельный явный `(with-current-buffer BUFFER (save-buffer))`.
Он сохраняет undo и штатно обслуживает file-modtime, backups и save hooks.
Ошибка сохранения не означает откат уже успешной буферной правки: нужно
показать её пользователю и оставить несохранённые изменения. Не имитировать
сохранение через `set-buffer-modified-p nil`, не обходить буфер shell-записью
и не использовать revert как обычную синхронизацию правок.

Краткая инструкция и сигнатура помещаются в system prompt; подробности —
в docstring. Это рекомендация, а не sandbox: unrestricted `eval_elisp` остаётся
единственным инструментом, никакого перехвата всех файловых операций нет.
Undo ограничен обычными лимитами Emacs и временем жизни буфера, не является
постоянной историей на диске.

## Уточнение после повторного live-теста

В новой сессии модель использовала helper и штатный `save-buffer`, но путала
нулевые индексы строк с абсолютными позициями буфера. Отказы OLD защищали от
ошибочных замен; после нескольких отказов модель обошла helper прямым `insert`.
Это не доказательство потери undo, но обход гарантий атомарного отдельного шага.

Принято пользователем:

- Явно объяснить в prompt/docstring: buffer positions начинаются с 1, string
  indices с 0. Индекс I текста, захваченного с позиции BASE, соответствует
  BASE+I. Для `buffer-string` BASE — `point-min` **в момент захвата**, который
  при narrowing не обязательно равен 1. Предпочитать координаты helpers.
- После OLD mismatch или stale tick перечитывать диапазон и заново получать
  OLD/позиции/tick, не угадывать сдвиги и не обходить отказ прямыми правками.
- Ошибка OLD mismatch содержит исходный диапазон, текущий tick и не более
  160 фактических символов его начала в escaped-представлении. Усечение явно
  помечено с количеством показанных/полных символов. Preview — диагностика,
  не автоматически найденная замена, не разрешение обойти проверку и не полный
  контекст вокруг диапазона. Отказ по-прежнему не меняет buffer state/undo.
  Общий `eval-output-limit` может дополнительно обрезать сообщение ошибки при
  маленькой настройке; preview не вводит отдельный output artifact.

## Проверка

ERT: исходный дефект `write-region` + fake modified, корректный `save-buffer`
без stale modtime и с undo, сохранность предыдущей пользовательской истории,
отдельные undo для нескольких замен, rollback при ошибке hook, несовпадение
OLD/tick, disabled undo/read-only, narrowing/widening, вставка/удаление/no-op,
конфликт с диском, выполнение через единственный `eval_elisp`. Дополнительно:
регрессия string-index/buffer-position со свежим перечитыванием и undo,
BASE при narrowing, bounded escaped mismatch preview без изменения состояния.
Обязательны полный offline suite и byte compilation с warnings-as-errors.
Live smoke с провайдером — отдельно, только opt-in.
