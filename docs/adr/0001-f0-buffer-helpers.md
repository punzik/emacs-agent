# ADR-0001: Helpers чтения и навигации F0

Статус: принято пользователем; реализовано в F0, проверено offline.
Изначальный per-line формат ниже заменён компактным `:text` в F0c:
[ADR-0004](0004-efficient-model-io.md), раздел 2. Остальные гарантии F0 сохранены.
Opt-in live smoke исходного чтения отдельно не выполнялся.

## Контекст

Агент терял пустые строки при нумерации текста и использовал относительный
аргумент `line-beginning-position` как абсолютный номер строки. Нужны небольшие
проверенные функции поверх живых буферов, без перестройки ядра.

## Решение

Добавить модуль `emacs-agent-helpers.el` с тремя обычными Elisp-функциями:

- чтение диапазона абсолютных строк указанного живого буфера;
- чтение окрестности явно заданного point, включая координаты и символ;
- получение сведений о буфере, координатах и modification tick.

Функции вызываются через единственный LLM tool `eval_elisp`. Новые advertised
инструменты, whitelist и sandbox не вводятся.

Согласованные правила:

- Результат — plist с текстом, координатами, modification tick и признаками
  усечения там, где возвращается текст.
- Строки нумеруются с 1, столбцы с 0; позиции — Emacs character positions,
  не байтовые смещения.
- Координаты абсолютны относительно всего буфера. Доступ за narrowing
  разрешён только при явном запросе временного widening с восстановлением
  исходных ограничений.
- Неверные диапазоны вызывают ошибку, без молчаливого clamp или выбора другого
  буфера. Умерший буфер и недопустимая позиция также не подменяются fallback.
- Завершающий newline оставляет доступную пустую строку на EOF.
- Читается живой буфер, включая несохранённые изменения, не файл с диска.
- Point, mark/region, narrowing, окна и содержимое буфера не меняются.
- Вывод явно сообщает усечение и координаты продолжения, в том числе внутри
  длинной строки. Modification tick не превращает старую позицию в marker
  и сам по себе не гарантирует её актуальность.

### Уточнение реализации

После чтения evaluator, context capture, adapter и тестов выбран следующий
небольшой API (BUFFER — живой объект или точное имя существующего буфера):

```elisp
(emacs-agent-buffer-info BUFFER &key tick)
(emacs-agent-read-lines BUFFER START END &key widen (limit 4096) from tick)
(emacs-agent-read-around BUFFER POSITION &key (before 2) (after 2)
                         widen (limit 4096) tick)
```

`START..END` включительны. Пустой буфер содержит строку 1. Столбец — display
column по `current-column`, включая расширение tabs. `:tick` проверяет ожидаемый
`buffer-chars-modified-tick`; без него допустимая численно старая позиция не
распознаётся как устаревшая. Identity задаётся текущим точным именем буфера;
имя не является вечным ID и не защищает от kill/recreate.

Metadata содержит `:buffer`, `:file`, `:point`, `:line`, `:column`, `:point-min`,
`:point-max`, `:narrowed`, `:modified`, `:tick`. В чтении bounds описывают
эффективные ограничения доступа (после явного `:widen t`, если он передан).
Текст представлен `:lines`: каждая строка содержит `:line`, `:start`, `:end`,
`:line-end`, `:text` без newline; конец исключительный, при усечении находится
до полного конца строки. Есть `:requested-lines`, фактически возвращённые
`:start`/`:end`, `:truncated` и `:next-position`. Продолжение — тот же диапазон
с `:from` и `:tick` из результата. Around добавляет `:at` с явной позицией,
её line/column и символом; окрестность ограничивается краями буфера.
Частично недоступные из-за narrowing строки не возвращаются молча как полные:
нужен явный widening либо ошибка. Внутреннее временное widening для расчёта
абсолютных координат не разрешает читать недоступный текст.

`limit` ограничивает текст в символах, включая разделители строк. Дополнительно
текст уменьшается до помещения **печатного plist** вместе с metadata и `\n=> `
в `emacs-agent-eval-output-limit`. Если даже metadata не помещается или нет
места для продвижения по непустому тексту, helper сигнализирует ошибку. Общий
evaluator не изменён. Гарантия действует для helper как единственной последней
формы, без stdout, при стандартных print settings evaluator; обёртка результата
в другой объект или дополнительный stdout может снова привести к общему
усечению. Полный output artifact относится к F3, не вводится здесь.

## Последствия и проверка

Сначала реализуется F0, затем F0b; остальные этапы не включаются в этот refactor.
Нужны ERT-регрессии обеих исходных ошибок, проверки пустых строк, EOF, Unicode,
tabs, narrowing, ошибочных координат, усечения и сохранности editor state.
Обязательны ERT и byte compilation с warnings-as-errors. Live smoke — отдельно,
только opt-in; offline проверки не считаются проверкой реального провайдера.

Основание и полный перечень критериев: [post-MVP roadmap](../POST_MVP_ROADMAP.md),
раздел F0.
