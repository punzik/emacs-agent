# ADR-0025: Диагностика и структурные правки Emacs Lisp

Статус: принято пользователем; последовательно реализованы диагностика,
JSON-структура и безопасная замена. Без paredit и новых model tools.

## Контракт

Обычные функции в `emacs-agent-sexps.el`, доступные через `eval_elisp`:

- `emacs-agent-check-sexps BUFFER &key start end tick widen`: plist с
  `:ok`, числом полностью прочитанных форм и первой диагностикой.
- `emacs-agent-inspect-sexps BUFFER &key start end tick widen depth limit`:
  JSON-строка с диапазонами форм и ограниченным деревом частей. Глубина и
  количество узлов ограничены явно; повреждённый хвост не скрывает уже
  прочитанные формы. Диагностика включается в JSON.
- `emacs-agent-replace-sexp BUFFER START END OLD NEW &key tick widen repair`:
  замена одной целой формы (в том числе вложенной), либо удаление через NEW="".
  NEW должен быть одной формой без окружающих пробелов/комментариев.
  В режиме `:repair t` исходный диапазон может быть произвольным и NEW может
  содержать несколько форм. В обоих случаях весь доступный буфер после правки
  должен успешно читаться. При narrowing проверяется только доступный текст
  как самостоятельный фрагмент, не весь файл. `:widen t` явно расширяет область.

Область диагностики/просмотра START..END трактуется как самостоятельный фрагмент
Emacs Lisp. Позиции абсолютные, END исключителен; строки 1-based, колонки
0-based display columns. Результаты содержат tick и проверенные границы.

## Основа и гарантии

Используется штатный Emacs Lisp reader, не подсчёт скобок и не собственная
реализация грамматики. Формы только читаются, не исполняются. Разбор происходит
на копии без text properties, с Elisp syntax table и syntax-propertize для
комментариев и подсказки о незакрытой форме. Чтение использует отдельный obarray
и отключённые symbol shorthands только на время встроенного `read`, не вокруг
всего обхода дерева: автозагрузка библиотек требует обычной таблицы символов.
Чтение не интернирует символы в пользовательской таблице и не вызывает пользовательские hash tests из `#s(hash-table ...)`.
Такие records читаются как общие records, без constructor-specific проверок
нативного hash table. Это намеренное ограничение структурной проверки, а не
попытка исполнять reader-конструкторы. Change/kill hooks копии не запускаются.
Reader проверяет также соответствие
скобок `()`/`[]`, строки и символьные литералы. При EOF синтаксическая подсказка
о незакрытой скобке/строке приблизительна; точка остановки reader и начало
непрочитанной формы возвращаются отдельно. Это не проверка смысла программы,
компиляции, доступности функций или того, где автор намеревался поставить скобку.

JSON сохраняет исходные диапазоны, а не сериализует прочитанные Lisp-объекты:
циркулярные объекты и reader-префиксы не превращаются в бесконечные деревья.
Раскрываются обычные списки, векторы и quote/backquote/unquote/function-префиксы;
остальные reader-конструкции остаются листьями. Для дочерних диапазонов с
`#N=/#N#` используется source-boundary fallback после успешного чтения родителя:
независимый повторный read теряет scope reader labels. Комментарии не являются узлами,
но сохраняются в исходных диапазонах и preview. Точка dotted pair — отдельная
синтаксическая часть, не выражение для замены.

Правка использует существующий `emacs-agent-replace-region`, сохраняя проверки
OLD/tick, read-only, undo, конфликтов с диском и hooks. Внешняя atomic change
group включает проверку фактического результата после hooks; ошибка или
output-budget failure откатывает текст целевого буфера. Проверка кандидата до
правки не заменяет проверку результата. Побочные эффекты hooks вне целевого
буфера не откатываются. Автоматического сохранения нет; unrestricted eval
по-прежнему может обойти эти хелперы.

## Проверка

ERT: корректные/повреждённые формы, строки, комментарии, символьные литералы,
несовпадающие типы скобок, координаты, narrowing/tick и сохранность состояния;
JSON depth/node limits, частичный разбор, prefixes/dotted pairs; замена,
удаление, repair, rollback после hooks, undo, no-op и старые edit guards.
451 ERT проходят как на исходниках, так и после byte compilation с
warnings-as-errors (29 новых sexp-тестов и один prompt-contract тест).
`git diff --check` проходит. Проверены также callbacks reader-конструкторов,
reader-label scope, dotted tails без пробелов, hooks с narrowing, сохранение
предыдущего user undo при rollback, disk conflicts и literal texts через
настоящий evaluator. Отдельные чистые процессы Emacs проверяют автозагрузку
CL-функций с исходным и автоматически выбранным модулем, без preloaded cl-extra. Проверки запускались через `nix-shell -p gnumake` с
установленным Emacs 30.2; минимум Emacs 28.1 отдельно не проверен. Без provider
calls, загрузки в пользовательский Emacs и новых runtime-зависимостей.
Поведение локальной модели в live-сессии пока не измерялось.
